Toutes les classes ci-dessous appartiennent à l’espace de noms `WindevReader`. Les méthodes `Open` acceptent un chemin et, en option, `WindevOpenOptions`.

## Points d’entrée

| Classe | Fichier | Données principales |
| --- | --- | --- |
| `WindevFile` | Toute famille reconnue | `Open` retourne `IWindevFile` selon le type PCS |
| `WindevDocument` | WDP, WDW, WDG, WDD, WDA, WDE | `Open` par extension ; sections et code communs |
| `WdpWindevProject` | WDP | `References`, `ConfigurationNames` |
| `WdwWindevWindow` | WDW | `Caption`, `Bounds`, `Elements`, `Preview` |
| `WdgWindevGlobalProcedures` | WDG | `Procedures`, `GlobalDeclarations` |
| `WddWindevAnalysis` | WDD | `Guid`, `Generation`, `Tables`, `Relations`, `SchemaDirectory`, `DecodedSchema` |
| `WdaWindevAnalysisSource` | WDA | `Sections` et buffers décodés |
| `WdeWindevReport` | WDE | `NoDataMessage`, `Elements` |
| `WdlWindevLibrary` | WDL, patch | `Entries`, `Header`, `DecodedProperties`, `DecodedDirectory` |
| `FicHfsqlDataFile` | FIC | En-tête et lecture à disposition explicite |
| `NdxHfsqlIndexFile` | NDX | Répertoire terminal et `IndexDescriptors` |
| `MmoHfsqlMemoFile` | MMO | Mots bruts et `RawHeaderSlots` |

`IWindevFile` expose `FileName`, `Name`, `RawData`, `Diagnostics`. Les documents ajoutent `Header`, `Kind`, `Sections`, `CodeBlocks`. Le nom retourné peut provenir des métadonnées ; il n’est pas nécessairement le nom du chemin d’entrée.

## Schéma

| Modèle | Propriétés utiles | Coordonnées |
| --- | --- | --- |
| `WindevDataTable` | `Id`, `Name`, `PhysicalName`, `Guid`, `Fields`, `RawRecordByteLength` | `Offset` dans `DecodedSchema` |
| `WindevDataField` | `Id`, `Name`, `Caption`, `RawTypeCode`, `Type`, `Size`, `StorageSize`, `RawFlags`, `RawCompositeMarker`, `IsCompositeKey` | `Offset` dans `DecodedSchema` |
| `WindevDataRelation` | Tables/rubriques source et cible avec identifiants, `Name`, `RawFlags`, `RawTrailer` | `Offset` dans `DecodedSchema` |
| `WindevSchemaDirectoryEntry` | `Name`, `Offset`, `Count` | Destination dans `DecodedSchema` |

`Type` est un libellé pour les codes rencontrés. Un code inconnu reste `Unknown`. Le code 38 du témoin 15 devient `AutomaticIdentifier32` ; ses quatre octets sont lus comme `Int32` par la disposition explicite. Un mémo de stockage 8 n’est pas interprété comme une chaîne de huit octets.

## Données physiques

| Membre | Contrat |
| --- | --- |
| `HasSameIdentityAs(other)` | Compare GUID d’analyse et de table |
| `MatchesAnalysis(analysis)` | Compare le GUID d’analyse |
| `FindTableDefinition(analysis)` | Retrouve une table avec les deux correspondances ; sinon `null` |
| `CreateFixedRecordLayout(analysis, dataOffset, recordCount)` | Profils WDD/FIC 28, 29 et 31 fixes recoupés ; noms/types depuis le schéma, début/compte explicites |
| `ReadFixedRecords(layout)` | Vue paresseuse `HfsqlFixedRecordView` des emplacements |
| `HfsqlFixedRecord.Values` | Dictionnaire de valeurs CLR par nom de champ |
| `HfsqlFixedRecord.RawData` | Octets exacts de l’emplacement, exclus du JSON |
| `ReadFlatIndex(index)` | Profil plat 15/24/25/29/31 au tag 7 ; clés et références brutes, sentinelle exclue |
| `ReadMemo(reference)` | Bloc MMO simple ; référence absolue, sans association FIC implicite |
| `ReadMemo(fic, reference)` | Même lecture, avec comparaison des deux GUID du propriétaire |
| `HfsqlMemoBlock.DecodeText(encoding)` | Longueur exacte, encodage CP1252 ou UTF-16LE explicitement choisi |
| `ReadIndexRegion(index)` | Octets entre descripteurs terminaux, pas un index logique reconstruit |

`HfsqlFixedRecordLayout` contient `DataOffset`, `RecordByteLength`, `RecordCount`, `Fields`. `HfsqlFixedField` contient `Name`, `Offset`, `ByteLength`, `Type`.

| Type explicite | Largeur | Valeur CLR / règle |
| --- | --- | --- |
| `UInt8` | 1 | `byte` |
| `Int16`, `UInt16` | 2 | `short`, `ushort` |
| `Int32`, `UInt32` | 4 | `int`, `uint` |
| `Int64`, `UInt64` | 8 | `long`, `ulong` |
| `Boolean8` | 1 | `bool` ; accepte seulement 0 et 1 |
| `Date8Z` | 9 | `string` de huit chiffres ASCII ; NUL à +8 ; calendrier non validé |
| `Cp1252Z` | Fournie | `string`, NUL obligatoire, CP1252 explicite |
| `Utf16LeZ` | Paire, fournie | `string`, NUL aligné, UTF-16LE strict |
| `Bytes` | Fournie | `byte[]`, base64 dans le JSON System.Text.Json |

Ces noms de types explicites ne sont pas les codes binaires HFSQL. Les entiers sont lus en petit-boutiste. Une disposition bornée peut rester sémantiquement incorrecte si l’appelant fournit de mauvais offsets.

## Buffers et extraction

`WindevSection.Offset` est absolu dans le fichier. `WindevDecodedBlock.Offset` est relatif à la section stockée. Les offsets des chaînes dépendent de la liste consultée : section brute ou buffer décompressé. Ne pas mélanger ces coordonnées.

`WindevWindowPreview` expose `BmpData`, `Width`, `Height`, `SaveBmp(path)`, `GetRgba32()`. `WindevLibraryChunk.PayloadRelativeOffset` est relatif à la charge utile WDL. Utiliser `ReadStoredChunk` pour éviter de recalculer manuellement la position fichier.


`HfsqlFlatIndex` expose `Offset`, `KeyByteLength`, `DeclaredEntryCount`, `TerminalSentinelOffset`, `Entries`. Chaque `HfsqlIndexEntry` donne son offset absolu, `Key` (mémoire exclue du JSON), `KeyHex` et les deux références `u64` brutes. Le lecteur valide les profils 15/24/25/29/31 observés et n’utilise pas les valeurs résiduelles d’autres régions comme entrées supplémentaires.


`HfsqlMemoBlock` expose `Offset`, `PayloadOffset`, `PayloadByteLength`, `StoredRegionByteLength` et `Data` (exclue du JSON). Les mots bruts restent accessibles avec des noms relatifs à leur position. Le décodage ne retire aucun NUL, préserve les zéros inclus dans la plage déclarée et vérifie les séquences UTF-16LE. Il n’effectue pas de détection d’encodage ni de parcours de chaînes de blocs. Les références de mémos issues de la disposition FIC sont de type CLR `ulong`.


Dans le profil source 15, les identités et titres sont CP1252 Z ; les lignes et auteurs utilisent des longueurs explicites. Les `WindevString` candidats du buffer de propriétés ont un offset au texte et une taille incluant NUL, avec le diagnostic `HeuristicLegacyStrings`. Ils ne représentent pas des propriétés entièrement interprétées. Les pages [chaînes](../file-formats/windev/chaines.mdx) et [WDW](../file-formats/windev/wdw.mdx) précisent les repères.


## Métadonnées des éléments WDW

| Membre / type | Contenu | Limite |
| --- | --- | --- |
| `WindevUiElement.Bounds` | `WindevBounds?` : X, Y, largeur et hauteur de conception | `null` si le descripteur n’est pas reconnu |
| `WindevUiElement.Caption` | `string?` : libellé lu à une position vérifiée | `null` si le profil de libellé n’est pas reconnu |
| `WindevUiElement.Layout` | `WindevUiLayout?` : provenance et valeurs brutes | Décodage WDW uniquement |
| `WindevUiLayout.DescriptorOffset`, `RawDescriptor` | Position et valeur du descripteur | Aucun type de contrôle déduit du seul descripteur |
| `IdentifierOffset`, `RawIdentifier` | Position et `u64` brut après le nom | Identifiant non interprété |
| `BoundsOffset` | Position de X dans le buffer décompressé | Y, largeur et hauteur suivent à +4, +8 et +12 |
| `CaptionOffset` | Position de la chaîne encadrée de libellé, optionnelle | Position décodée, pas compressée |
| `CommonTailOffset` | Repère `E` après la chaîne commune ou sa sentinelle nulle | Optionnel si la forme n’est pas reconnue |
| `RawValues` | Vues `WindevUiRawValue(Offset, ByteLength, Value)` | Inspection brute ; utiliser `Interaction` pour les paramètres d’état calculés |

Le constructeur existant de `WindevUiElement` reste inchangé ; les trois nouveaux membres sont des propriétés initialisables. Consulter la [carte WDW](../file-formats/windev/wdw.mdx#position-taille-et-libellé-des-champs) pour le périmètre exact des profils.


## Interaction initiale des champs WDW

| Membre / type | Contenu | Inconnu |
| --- | --- | --- |
| `WindevUiElement.Interaction` | `WindevUiInteraction?` pour un descripteur compatible 28/29/31 | `null` si le profil n’est pas appliqué |
| `IsVisible` | Visibilité initiale enregistrée (`bool?`) | `null` si le mot n’est ni 0 ni 1 |
| `State` | État initial (`WindevControlState?`) | `null` si le code n’est pas reconnu ou pas localisé |
| `IsTabStop` | Accès par Tab enregistré (`bool?`) | `null` si le mot est inconnu ou non localisé |
| `WindevUiInteraction.VisibilityOffset`, `RawVisibility` | Position décodée et mot `u32` de visibilité | Valeur brute conservée |
| `StateOffset`, `RawStateCode` | Position calculée et mot `u32` d’état, tous deux optionnels | Absents si les textes précédents ne sont pas reconnus |
| `TabAccessOffset`, `RawTabAccess` | Position calculée et mot `u32` d’accès par Tab, optionnels | Absents si le parcours ou les bornes ne sont pas valides |

| `WindevControlState` | Code brut observé | Sens |
| --- | --- | --- |
| `Active` | 0 | Actif |
| `Inactive` | 1 | Inactif |
| `GrayedOut` | 4 | Grisé |

L’énumération n’est pas un jeu de drapeaux : les combinaisons ne sont pas déduites. Ces valeurs décrivent le fichier source, sans exécuter le WLangage. Les paramètres de visibilité et de Tab sont distincts de l’état ; ils ne sont pas recalculés à partir de celui-ci.


## Clés du schéma WDD

| Membre / type | Contenu | Limite |
| --- | --- | --- |
| `WindevDataField.Key` | `WindevFieldKey?` : mot de nature et composants | Profils 28/31 ; `null` dans les autres versions |
| `KeyKind` | `WindevKeyKind?` : `None`, `Duplicates`, `Primary` | Codes 0/2/4 ; autres codes inconnus |
| `IsPrimaryKey` | `bool?` | `null` si la nature n’est pas reconnue |
| `AllowsDuplicates` | `bool?` | `null` pour une non-clé ou une nature inconnue |
| `KeyComponents` | `IReadOnlyList<WindevKeyComponent>` | Liste ordonnée ; vérifier aussi `ComponentsDecoded` |
| `WindevFieldKey.Offset`, `RawKind` | Position de `Q+27` et mot `u16` brut | Offset dans le schéma décompressé |
| `ComponentsOffset` | Position du vecteur pointé par `Q+46` | Optionnelle ; profil composé reconnu uniquement |
| `ComponentsDecoded` | Vecteur lu et références résolues | Faux pour les rubriques non composées |
| `WindevKeyComponent` | `FieldOrdinal`, `FieldId`, `FieldName`, `RawOptions`, `Offset` | Ordinal local, options et position de l’entrée brute |

Les numéros de composants sont distincts des identifiants de rubrique. Les options non nulles ne sont pas converties en une direction de tri. Les règles d’intégrité, nullité et unicité des codes non vérifiés ne sont pas reconstituées.
