Le code source est rangé par propriétaire et par événement. Le lecteur restitue les lignes de source présentes dans les documents ; il n’exécute pas le code et ne décompile pas le bytecode des exécutables.

Les positions sont exprimées en **octets**. Les inconnues sont indiquées comme telles ; voir les [conventions](../conventions.mdx).

## Localisation du code

Dans les projets complets, fenêtres, collections de procédures et états étudiés, la section 2 porte le tag PCS 02. Elle contient quatre octets auxiliaires, puis une enveloppe LZW à +4.

Les positions ci-dessous se rapportent au buffer **décompressé**, noté `D`. Ce buffer contient des descriptions de groupes, des événements, des lignes source et des métadonnées supplémentaires. Il ne correspond pas à un simple fichier texte concaténé.

## Groupes et propriétaires

Le propriétaire initial est le nom du document. Une chaîne encadrée de nom suivie du tag `0D` fournit ensuite un nouveau propriétaire pour les événements suivants : procédure, contrôle ou bloc d'état.

| Position relative à un groupe | Taille | Type | Commentaire |
| --- | --- | --- | --- |
| Avant `G` | Variable | Chaîne encadrée de nom, lorsque présente | Nom du propriétaire |
| `G + 0` | 1 | `u8` | Tag observé `0D` |
| `G + 1` | 4 | `u32` | Longueur du groupe observée ; organisation complète non interprétée |
| Après `G + 5` | Variable | `octets[n]` | Identifiants, listes et autres données internes |
| À l'intérieur du groupe | Variable | Enregistrements d'événement | Structures décrites ci-dessous |

La bibliothèque utilise le nom de groupe précédent comme contexte. Elle ne reconstruit pas encore un arbre complet de tous les enregistrements du buffer.

## En-tête d'un événement source

Soit `E` le début de l'événement et `B` sa longueur stockée à +1 :

| Offset relatif à `E` | Taille | Type | Champ | Valeur / commentaire | Statut |
| --- | --- | --- | --- | --- | --- |
| `+0` | 1 | `u8` | Variante de l'enregistrement | `15` ou `16` en hexadécimal | Vérifié |
| `+1` | 4 | `u32` | Longueur du corps `B` | Taille totale de l'événement = `5 + B` | Vérifié |
| `+5` | 4 | `u32` | Nombre de lignes `N` | Nombre de lignes source à lire | Vérifié |
| `+9` | 2 | `u16` | Identifiant d'événement brut | Code numérique ; correspondance avec les noms d'événements non validée | Structure vérifiée, sens partiel |
| `+11` | 2 | `u16` | Identifiant de langue brut | Exemple 11 ; ne pas supposer un code ISO | Observé |
| `+13` | 4 | `u32` brut | Mot auxiliaire A | 0 dans l'exemple détaillé | Sens inconnu |
| `+17` | 4 | `u32` brut | Mot auxiliaire B | 1 dans l'exemple détaillé | Sens inconnu |
| `+21` | Variable | Lignes source | Début du premier enregistrement de ligne | Vérifié |
| Après les `N` lignes | Variable | `octets[n]` | Métadonnées jusqu'à `E + 5 + B` | Non entièrement interprétées |

Les tags 15 et 16 ne sont pas la version majeure WINDEV : ce sont des variantes d'enregistrement. Le profil illustré par SuperMailExtra contient des événements 15 ; celui illustré par SuperNoteExtra contient des événements 16. Les deux emploient le début de lignes à +21 dans les structures reconnues.

## Ligne source non vide

Soit `L` le début de la ligne, `C_t` la taille de la chaîne de texte et `C_a` celle de l'auteur :

| Offset relatif à `L` | Taille | Type | Valeur / commentaire |
| --- | --- | --- | --- |
| `+0` | 1 | `u8` | Tag `03` |
| `+1` | `C_t` | Chaîne encadrée | Texte exact de la ligne |
| `+1 + C_t` | `C_a` | Chaîne encadrée | Identité de l'auteur |
| `+1 + C_t + C_a` | 4 | `u32` | Timestamp brut ; époque et fuseau non certifiés |
| `+5 + C_t + C_a` | 8 | `octets[8]` | Métadonnées restantes ; rôle inconnu |

```text
taille_ligne_non_vide = 1 + C_t + C_a + 12
```

Les tabulations et accents font partie du texte. Le lecteur n'ajoute pas automatiquement un nom de procédure à une ligne ni ne traduit le WLangage.

## Ligne source vide

| Offset relatif à `L` | Taille | Type | Valeur / commentaire |
| --- | --- | --- | --- |
| `+0` | 1 | `u8` | Tag `03` |
| `+1` | 1 | `u8` | Sentinelle `00` : texte vide |
| `+2` | `C_a` | Chaîne encadrée | Auteur |
| `+2 + C_a` | 4 | `u32` | Timestamp brut |
| `+6 + C_a` | 8 | `octets[8]` | Métadonnées restantes |

```text
taille_ligne_vide = 2 + C_a + 12
```

Une ligne vide conserve donc une identité d'auteur et un timestamp. La supprimer ferait perdre à la fois le formatage du source et des positions binaires.

## Exemple fictif : déclarations globales de SuperNoteExtra

Le premier événement source reconnu du buffer WDG commence à `D[37]`, soit `0x0025` :

```text
16 DB 02 00 00 05 00 00 00 00 00 0B 00 00 00 00 00 01 00 00 00
```

| Champ | Position dans `D` | Valeur |
| --- | --- | --- |
| Tag | 37 | `0x16` |
| Longueur du corps | 38 | 731 |
| Taille complète | Calculée | 736 |
| Nombre de lignes | 42 | 5 |
| Identifiant d'événement | 46 | 0 |
| Identifiant de langue | 48 | 11 |
| Première ligne | 58 | Tag `03` |
| Fin de l'événement | 773, exclu | L'événement suivant peut commencer à cette position |

La première ligne est `St_ResultatChaineFlags est une structure`. Sa chaîne encadrée commence à 59, mesure 53 octets, puis la chaîne d'auteur mesure 27 octets. La première ligne complète mesure `1 + 53 + 27 + 12 = 93` octets ; la deuxième commence à 151.

## Reconnaissance et limites

| Contrôle | Commentaire |
| --- | --- |
| Tag d'événement 15 ou 16 | Identifie une variante prise en charge |
| Taille de corps dans le buffer | Évite un dépassement |
| Chaque ligne commence par 03 | Distingue source et autres chaînes |
| Texte vide ou chaîne encadrée valide | Contrôle le encadrement |
| Auteur encadré valide | Empêche d'assimiler une chaîne isolée à du code |
| Douze octets de métadonnées présents | Conserve le bon curseur |
| `N` lignes lues à l'intérieur de l'événement | Vérifie le compte annoncé |

Les événements sans aucune ligne ne produisent pas de bloc source dans le lecteur actuel. Les métadonnées compilées, les éventuels enregistrements d'une autre variante et les significations exhaustives des numéros restent non interprétés.

`Source` dans l'API reconstruit un texte avec `CRLF` entre les lignes. Ces caractères de séparation ne sont pas des octets de fin de ligne stockés entre les enregistrements binaires décrits ici.
