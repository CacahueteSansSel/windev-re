Commandes CLI

L’outil se lance avec dotnet artifacts/cli/WindevReader.Cli.dll. Dans les exemples suivants, WindevReader.Cli.dll désigne ce fichier ; conserver les DLL et fichiers runtime du même dossier ensemble.

CommandeRésultat
inspect FICHIERRésumé JSON de la famille et des structures exposées
json FICHIER [SORTIE]Modèle JSON complet, sans les mémoires binaires exclues du modèle
code FICHIER [SORTIE]Source WLangage des documents source reconnus
preview WDW SORTIE.bmpBMP de prévisualisation
extract-resource WDL INDICE SORTIERessource d’une entrée WDL
layout FIC WDD DEBUT COMPTE [SORTIE]Disposition fixe nommée depuis un WDD 15, 24, 25, 28, 29 ou 31 compatible
index-entries NDX INDICE [SORTIE]Clés et références du profil plat NDX 15/24/25/29/31 reconnu
records FIC DISPOSITION.json [SORTIE]Valeurs des emplacements physiques de la disposition explicite
memo MMO REFERENCE ENCODAGE [SORTIE]Texte d’un bloc simple avec encodage explicite
corpus DOSSIER [SORTIE]Rapport récursif d’ouverture des familles reconnues

Sans argument de sortie facultatif, le résultat textuel est écrit sur la sortie standard. Le code retour est 0 en cas de succès, 1 pour une erreur traitée et 2 lorsque les arguments initiaux sont insuffisants. Les arguments DEBUT, COMPTE et INDICE sont des entiers décimaux ; les indices commencent à zéro.

Schéma puis valeurs​

Utiliser le WDD fourni qui correspond au couple PERSONNE. Le nom SuperNoteExtra ci-dessous est un nom fictif de présentation.

dotnet WindevReader.Cli.dll inspect SuperNoteExtra.wdd
dotnet WindevReader.Cli.dll layout PERSONNE.fic SuperNoteExtra.wdd 1776 5 disposition.json
dotnet WindevReader.Cli.dll records PERSONNE.fic disposition.json emplacements.json

Le fichier de disposition contient DataOffset, RecordByteLength, RecordCount, Fields. Chaque champ déclare Name, Offset, ByteLength, Type. Les offsets de champs sont relatifs à l’emplacement.

{
  "DataOffset": 1776,
  "RecordByteLength": 124,
  "RecordCount": 5,
  "Fields": [
    { "Name": "IDPERSONNE", "Offset": 9, "ByteLength": 8, "Type": "Int64" },
    { "Name": "FLAGADMIN", "Offset": 123, "ByteLength": 1, "Type": "Boolean8" }
  ]
}

Cette disposition minimale ne lit que deux rubriques. layout produit les cinq rubriques du profil confirmé. Le nombre d’emplacements exportés ne constitue pas un nombre de lignes actives.

dotnet WindevReader.Cli.dll code ProceduresGlobales.wdg procedures.wl

L’indice 1 est un exemple du patch étudié ; consulter son inventaire avant de sélectionner une entrée. corpus exclut les WDU textuels voisins des patchs et n’écrit pas de fichiers extraits.

Fichiers 31​

dotnet WindevReader.Cli.dll layout jour_ferie.fic SuperNoteExtra.wdd 1763 8 jours-layout.json
dotnet WindevReader.Cli.dll records jour_ferie.fic jours-layout.json jours.json
dotnet WindevReader.Cli.dll layout semaine_cours.fic SuperNoteExtra.wdd 1627 1 semaines-layout.json
dotnet WindevReader.Cli.dll index-entries jour_ferie.ndx 3 mois-jour-index.json

Le WDD doit être celui des tables 31. La clé composée de l’indice 3 est vérifiée dans le témoin JOUR_FERIE ; cet indice ne nomme pas la même rubrique dans tous les NDX.

Mémo du témoin 29​

dotnet WindevReader.Cli.dll layout PERSONNE.fic SuperMailExtra.wdd 1730 1 personne29-layout.json
dotnet WindevReader.Cli.dll records PERSONNE.fic personne29-layout.json personne29.json
dotnet WindevReader.Cli.dll memo PERSONNE.mmo 210 cp1252 description.txt

La commande memo travaille sur une référence absolue explicite ; elle ne reçoit pas le FIC et n’en vérifie donc pas les GUID. Utiliser l’overload C# avec propriétaire pour cette vérification supplémentaire. La sortie texte utilise le comportement d’écriture UTF-8 habituel de la CLI, après décodage de la source CP1252 ou UTF-16LE.
