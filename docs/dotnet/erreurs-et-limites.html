Erreurs et compatibilité

Traiter un refus​

using WindevReader;

try
{
    IWindevFile file = WindevFile.Open("SuperNoteExtra.wdd");

    foreach (WindevDiagnostic diagnostic in file.Diagnostics)
    {
        Console.WriteLine($"{diagnostic.Code}: {diagnostic.Message}");
    }
}
catch (UnsupportedWindevFormatException e)
{
    Console.Error.WriteLine($"Profil non pris en charge : {e.Message}");
}
catch (WindevFormatException e)
{
    Console.Error.WriteLine($"Structure invalide : {e.Message}");
}
catch (IOException e)
{
    Console.Error.WriteLine($"Erreur de lecture : {e.Message}");
}

UnsupportedWindevFormatException dérive de WindevFormatException, qui dérive de IOException. L’ordre des captures compte. WindevFormatException.Offset peut préciser la position de l’erreur ; cette position appartient au buffer vérifié, qui peut être un schéma décompressé plutôt que le fichier.

Les dispositions explicites sont validées à la construction de la vue. Les erreurs de contenu, dont une chaîne sans NUL ou un booléen hors 0/1, apparaissent à la lecture de l’emplacement concerné.

Fixer les budgets​

WindevOpenOptions options = new WindevOpenOptions
{
    MaxFileBytes = 32 * 1024 * 1024,
    MaxDecodedBlockBytes = 16 * 1024 * 1024,
    MaxTotalDecodedBytes = 64 * 1024 * 1024
};
IWindevFile fileWithOptions = WindevFile.Open("SuperNoteExtra.wdd", options);

Les extractions WDL ultérieures ont leurs propres vérifications de taille ; MaxTotalDecodedBytes n’est pas un compteur permanent de toutes les extractions déjà faites. Les dispositions FIC utilisent des vues paresseuses et des bornes calculées contre le fichier ; l’appelant reste responsable du volume qu’il choisit de matérialiser ou sérialiser.

Accepter une version de conteneur ne certifie pas toutes ses variantes internes. AllowUntestedVersions ne désactive ni les contrôles de format ni les budgets.

Limites fonctionnelles​

Le lecteur ne réécrit pas les fichiers, n’exécute pas le WLangage, ne reconstruit pas les fenêtres source depuis le bytecode et ne rend pas les états. Le décodage HFSQL reste partiel : début et compte des emplacements explicites, états logiques inconnus, parcours général du B-tree NDX et allocation générale des mémos non pris en charge ; les clés des profils plats 15/24/25/29/31 et des blocs simples MMO sont accessibles. L’absence de mot de passe n’est pas détectée automatiquement.

La validation binaire précise les témoins, les recoupements et les questions ouvertes.

Propriétés des champs WDW​

Elements reste un inventaire partiel de candidats. Un candidat peut avoir Bounds == null sans que l’ouverture de la fenêtre échoue. La lecture des rectangles exige un nom encadré conforme et le descripteur 607 (24/25/29) ou 610 (31). Des dimensions négatives font abandonner ce décodage local ; les noms et buffers restent accessibles.

Un libellé endommagé ou absent du profil ne déclenche pas une recherche libre dans les chaînes voisines. Les propriétés de visibilité, opacité, état, accès par Tab et type de saisie restent inconnues, même quand des valeurs brutes compatibles avec une valeur attendue sont présentes.
