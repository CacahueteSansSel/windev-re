Format WDD : schéma de données

Exemples fictifs. Les noms, chemins et identifiants applicatifs sont anonymisés. Les cartes de sections sont des profils numériques de référence ; les extraits textuels sont des exemples autonomes. Voir les conventions des exemples.

Identification​

PropriétéValeur

Version du produit observée31

Le WDD contient la description du schéma, pas les enregistrements des fichiers de données .fic, .ndx ou .mmo. Les tailles et types ci-dessous décrivent les métadonnées du schéma ; ils ne constituent pas une spécification du stockage physique de chaque valeur HFSQL.

Un compte nul peut être associé à un pointeur égal à la fin du buffer ou à une position partagée avec une autre région. Il ne justifie pas de lire un enregistrement à cette position.

L'identification de l'entrée 2 comme répertoire de relations vient du lecteur étudié ; tous les spécimens ont un compte nul. La représentation d'une relation non vide n'est donc pas validée.

Somme de contrôle​

somme = 0
p = 8
pendant qu'il reste au moins quatre octets :
    somme = (somme + lire_u32(H, p)) modulo 2^32
    p = p + 4
pour chaque octet restant :
    somme = (somme + H[p]) modulo 2^32
exiger somme = lire_u32(H, 4)

Exemple arithmétique fictif, indépendant de la carte du WDD : une région à sommer contenant 04 03 02 01 FE FF FF FF 07 08 produit les valeurs suivantes.

ÉtapeValeur / type
Premier mot0x01020304, u32
Deuxième mot0xFFFFFFFE, u32
Deux octets restants7 et 8, deux u8
Somme modulo 2^320x01020311
Octets de cette somme dans un champ u3211 03 02 01

Pour un WDD concret, la somme stockée est à H[4] et doit être comparée au résultat calculé sur la totalité de H[8..fin]. Une modification d’un nom ou d’un GUID impose de la recalculer.

Ce contrôle fournit une validation indépendante du fait de retrouver quelques noms lisibles dans la sortie.

Relations et propriétés encore inconnues​

Le répertoire retenu pour les relations annonce zéro élément dans tous les WDD fournis. Aucun décodeur sémantique de relations non vides n'est présenté.

Les clés, contraintes, valeurs par défaut, connexions, encodages protégés et autres flags ne sont pas entièrement interprétés. Les flags sont exposés comme u32 brut, sans nommer chaque bit d'après une simple corrélation de valeurs.
