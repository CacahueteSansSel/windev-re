NDX : index et descripteurs

Le NDX accélère les parcours et les recherches. L’étude reconnaît son répertoire terminal et ses descripteurs de 60 octets ; elle ne reconstitue pas encore les clés ni le parcours du B-tree.

Les positions sont exprimées en octets. Les inconnues sont indiquées comme telles ; voir les conventions.

Structure déterminée​

Le type est 0x00070002. Après l’en-tête commun, un compte et un pointeur annoncent un répertoire terminal de positions sur 64 bits. Le découpage a été vérifié sur les 160 NDX initiaux, représentant quatre contenus distincts, puis sur PERSONNE.ndx en WINDEV 28.

Les positions sont exposées comme débuts de régions/descriptions d’index. Le profil plat 31 du cas jours et semaines permet désormais de lire des clés en clair. Les comparateurs généraux, liens de pages et parcours B-tree restent inconnus.

API​

var index = NdxHfsqlIndexFile.Open(@"D:\Projet\SuperNoteExtra\RADFic.ndx");
Console.WriteLine(index.DeclaredIndexCount);
Console.WriteLine(index.DirectoryOffset);
foreach (int position in index.IndexDescriptorOffsets)
    Console.WriteLine(position);
ReadOnlyMemory<byte> region = index.ReadIndexRegion(0);

La bibliothèque valide les bornes et préserve les octets sans les traduire en clés ou en enregistrements FIC.

Descripteur terminal de 60 octets​

Les pointeurs du répertoire désignent des descripteurs de 60 octets dans tous les contenus NDX étudiés. Les types ci-dessous décrivent le découpage retenu ; ils ne prouvent pas les types employés dans le code source du moteur. Les entiers sont en petit-boutiste.

Offset relatif au descripteur DTailleType de lectureAPI / commentaire

+24u32Longueur 60 ; valeur vérifiée à l’ouverture
+64u32 brutRawWordAt6, vaut 0x01000000 dans les profils
+104u32 brutRawWordAt10 ; pas un compte de lignes établi
+142u16 brutRawWordAt14 ; pas un type de rubrique établi
+168u64 brutRawPointerAt16 ; 0xFFFFFFFFFFFFFFFF dans les profils RAD
+244u32 brutRawLengthAt24 ; longueur observée d’une région dans PERSONNE
+288u64 brutRawPointerAt28 ; position d’une autre structure, y compris avant D
+368u64 brutRawPointerAt36 ; autre position physique
+4416u32[4] brutsRawTailWords ; tous nuls dans PERSONNE

IndexDescriptors expose ces champs. Les valeurs sentinelles des pointeurs bruts restent des ulong ; elles ne sont pas converties en adresses exploitables. Le lecteur ne suit pas ces pointeurs et ne leur attribue pas encore de rôle de racine B-tree, de liste libre ou de feuille.

Dans PERSONNE, le premier descripteur est situé à 5 034, tandis que RawPointerAt28 vaut 135. Le premier descripteur n’est donc pas nécessairement le début de l’index logique. ReadIndexRegion(i) conserve son contrat historique : il renvoie les octets entre deux descripteurs consécutifs, ou jusqu’au répertoire terminal. Ce n’est pas une reconstruction des pages de l’index. Voir la carte complète du cas PERSONNE.

Lire le profil plat 31​

ReadFlatIndex(i) expose un en-tête de 29 octets au tag 7, puis des clés de largeur fixe et deux références brutes par entrée. Le compte inclut une sentinelle tout à 1, retirée de la liste Entries. Les tableaux ont été recoupés avec tous les emplacements des deux nouveaux FIC, soit sept tableaux et 35 clés. Ce décodage ciblé ne s’applique ni aux NDX RAD opaques ni au profil PERSONNE 28. Les tables d’offsets et limites détaillent ce profil.
