FIC : emplacements et valeurs

Le FIC stocke les valeurs et des structures de gestion. Un emplacement physique n’est pas nécessairement un enregistrement actif. Le cas PERSONNE fournit un profil fixe dont les rubriques sont maintenant confirmées par le WDD.

Les positions sont exprimées en octets. Les inconnues sont indiquées comme telles ; voir les conventions.

Structure reconnue​

Le type 0x00070001 identifie les FIC étudiés. Les 90 premiers octets suivent l’en-tête physique commun. Le reste demeure disponible dans UninterpretedBody.

Les tailles des rubriques du WDD ne suffisent pas à découper le FIC en lignes : il faut aussi connaître les structures de gestion, les états d’enregistrement, les valeurs variables et la protection éventuelle.

Protection et résultats des essais​

La transformation WDD utilisée telle quelle n’a pas fourni de structure FIC validée. Le paramètre fixe des métadonnées WDL n’a pas non plus donné de structure validée dans les régions FIC examinées. Ces essais bornés n’identifient pas l’algorithme de protection et ne constituent pas une recherche exhaustive de mot de passe.

Pour les fichiers RAD, le corps reste brut ; aucun mot de passe n’est exposé. Le GUID d’analyse RAD diffère de celui du WDD applicatif fourni, qui ne peut pas être appliqué arbitrairement à ces octets.

API​

var fichier = FicHfsqlDataFile.Open(@"D:\Projet\SuperNoteExtra\RADFic.FIC");
Console.WriteLine(fichier.Header.TableGuid);
Console.WriteLine(fichier.PasswordStatus); // Unknown
ReadOnlyMemory<byte> corps = fichier.UninterpretedBody;

Une ouverture réussie valide les champs pris en charge, pas la découverte automatique des enregistrements. ReadFixedRecords(layout) permet désormais une lecture des emplacements en clair lorsque l’appelant connaît leurs positions et types. Le cas PERSONNE sans mot de passe donne une disposition vérifiée de cinq emplacements de 124 octets. Cette disposition ne s’applique pas aux fichiers RAD et ne reconstitue pas leur schéma.

Relier les valeurs au schéma​

Dans le cas PERSONNE 28, le WDD confirme IDPERSONNE (8 octets), NOM (51 octets stockés pour 50 déclarés), PRENOM (51), AGE1 (4), FLAGADMIN (1). Le pas de 124 est présent dans le WDD et le WDA. La lecture n’a plus besoin de noms ou de types de travail ; elle conserve un début de données et un compte explicites.

Le guide .NET utilise CreateFixedRecordLayout. Le cas complet garde la carte du fichier et des octets de gestion. Le profil de neuf octets de préfixe est vérifié sur ce témoin ; il n’est pas généralisé aux FIC opaques RAD.

Extension aux valeurs 31​

Les nouveaux témoins JOUR_FERIE et SEMAINE_COURS reprennent le préfixe observé de neuf octets. Leurs pas sont 70 et 35, avec des débuts de données à 1763 et 1627. Les dates stockent huit chiffres ASCII suivis de NUL. Une clé composée du schéma, MOISJOUR, n’occupe aucun octet de valeur supplémentaire dans le FIC. Voir le cas 31.
