Le WDG regroupe des procédures réutilisables et des déclarations globales. Les noms et les lignes de source sont distincts des métadonnées de l’éditeur.

Les positions sont exprimées en **octets**. Les inconnues sont indiquées comme telles ; voir les [conventions](../conventions.mdx).

Pour utiliser le lecteur, consulter la [documentation .NET](../../dotnet/index.mdx).

## Identification

| Propriété | Valeur |
| --- | --- |
| Extension | `.wdg` |
| Type PCS | `0x00000007` |
| Sections | 9 |
| Début des sections dans les spécimens | 202, soit `0x00CA` |
| Versions étudiées | 28 et 31 |

Une collection WDG contient des déclarations globales et des groupes de procédures. Elle ne doit pas être interprétée comme un unique texte source compressé.

## Section 0 : nom de collection

| Offset relatif | Taille | Type | Valeur / commentaire |
| --- | --- | --- | --- |
| `+0` | 4 | `u32` brut | 7 dans les spécimens |
| `+4` | 32 | Chaîne encadrée | `ProcéduresGlobales` |
| Après la chaîne | Variable | Métadonnées brutes | Identifiants et autres paramètres |
| Plus loin | Variable | Chaîne encadrée | Chemin vers le projet `.wdp` |

Le nom encadré occupe 32 octets, à cause de l'encodage UTF-8 de `é`. Pour SuperNoteExtra, il commence à l'offset fichier 206.

## Section 2 : préfixe et décompression

| Élément | SuperNoteExtra 31 | SuperMailExtra 28 |
| --- | --- | --- |
| Début de section dans le fichier | 353 | 349 |
| Préfixe de quatre octets | `00 00 00 00` | `0F 00 00 00` |
| Enveloppe LZW, début fichier | 357 | 353 |
| Flux LZW, début fichier | 368 | 364 |
| `L` | 9 562 | 5 058 |
| `U` | 37 286 | 16 123 |
| Taille complète de section | 9 577 | 5 073 |

La valeur du préfixe n'est pas prise comme une taille. Le lecteur consomme exactement quatre octets auxiliaires, puis lit l'enveloppe.

## Déclarations globales

Les événements initiaux sont rattachés au nom de la collection, tant qu'aucun nom de procédure suivi d'un groupe 0D n'a été trouvé. Ils peuvent contenir une structure, des variables et des lignes vides.

Dans SuperNoteExtra, les déclarations comprennent notamment `St_ResultatChaineFlags est une structure`. Les événements ont la structure décrite dans le [chapitre WLangage](./wlangage.mdx).

## Groupes des procédures

Une procédure est identifiée par un nom encadré dans le buffer décompressé. Les événements suivants lui sont associés. La procédure peut avoir plusieurs événements ; l'API les conserve séparément avec leurs identifiants numériques.

## Sections secondaires

Les sections 3, 4 et 7 possèdent des frontières connues et des octets lisibles, mais leur schéma de propriétés n'est pas entièrement interprété. Les sections de longueur nulle doivent rester dans le répertoire logique ; les supprimer changerait les indices de sections.

## Limites

Les noms, déclarations et lignes source sont lisibles. Le bytecode, les informations détaillées de compilation, les identifiants internes et toutes les propriétés de l'éditeur ne sont pas décodés. Les événements sans ligne n'apparaissent pas comme des blocs source.
